# Niz_Week7_Keyword

### 1. 미들웨어 (Middleware)

→ '가운데(Middle)'에서 '소프트웨어(Ware)'들을 연결해 주는 가교 역할
→ 주로 클라이언트의 요청(Request)이 서버의 메인 로직에 도달하기 전이나,
    응답(Response)이 나가기 직전에 특정 작업을 수행함.

- **주요 역할:**
    - **인증:** 사용자가 로그인했는지, 권한이 있는지 확인.
    - **로깅(Logging):** 들어오는 모든 요청의 시간, IP, 경로 등을 기록.
    - **데이터 파싱:** JSON이나 Form 데이터를 서버가 이해할 수 있는 객체로 변환.
    - **에러 처리:** 하위 로직에서 발생한 에러를 잡아 공통된 형식으로 응답.
- **비유:** 공항의 '보안 검색대'와 같음.
비행기(메인 로직)를 타기 전에 티켓 확인(인증)과 소지품 검사(필터링)를 거치는 과정.

### 2. HTTP 상태 코드

→ 서버가 클라이언트의 요청에 대해 어떤 결과가 나왔는지 알려주는 **'세 자리 숫자'** 약속.

| **대역** | **의미** | **주요 예시** |
| --- | --- | --- |
| **2xx (Success)** | "잘 됐어!" | **200 OK**: 성공 / 
**201 Created**: 생성 성공 |
| **3xx (Redirection)** | "다른 데로 가봐" | **301 Moved Permanently**: 주소 옮겨짐 /
**304 Not Modified**: 캐시 써도 됨 |
| **4xx (Client Error)** | "네(클라이언트)가 잘못했어" | **400 Bad Request**: 잘못된 요청 /
**401 Unauthorized**: 인증 필요 /
**403 Forbidden**: 권한 없음 /
**404 Not Found**: 페이지 없음 |
| **5xx (Server Error)** | "내(서버)가 잘못했어" | **500 Internal Server Error**: 서버 내부 오류 / 
**503 Service Unavailable**: 서버 점검 중 |

### 3. 에러 핸들링 (Error Handling)

→ 프로그램 실행 중 발생하는 예기치 못한 상황(에러)을 정의하고,
    프로그램이 멈추지 않도록 적절히 대응하는 프로세스.

- **핵심 기법:**
    - **Try-Catch-Finally:** 에러가 날 법한 코드를 `try`에 넣고,
    발생 시 `catch`에서 처리하며, 마지막에 `finally`로 자원을 정리.
    - **Global Error Handler:** 모든 에러를 한곳으로 모아 일관된 응답 형식(JSON 등)으로
    클라이언트에게 돌려주는 미들웨어를 구축.

### 4. Tsoa (TypeScript OpenAPI)

→ Node.js 환경에서 **TypeScript**를 기반으로 REST API를 구축할 때 사용하는 라이브러리.

- **주요 특징:**
    - **코드 우선:** TypeScript 클래스와 데코레이터(`@Route`, `@Get` 등)를 이용해 코드를 작성하면, 자동으로 **Swagger(OpenAPI) 문서**를 생성.
    - **강력한 타입 안전성:** 요청 데이터의 유효성 검사(Validation)를 TypeScript 인터페이스나 타입 정의를 기반으로 자동으로 수행.
    - **생산성 향상:** 문서를 따로 업데이트할 필요가 없어 코드와 문서 사이의 불일치 문제 해결.
- **작동 방식:**
    1. TypeScript 컨트롤러 작성.
    2. Tsoa가 코드를 분석하여 `routes.ts` 파일과 `swagger.json` 생성.
    3. 런타임에서 자동으로 유효성 검사 미들웨어 실행.
