# Niz_Week9_Keyword

## 1. OAuth 2.0 (프레임워크 / 프로토콜)

- 정의: 나를 대신해 다른 서비스의 자원에 접근할 수 있는 권한을 안전하게 위임(Authorization)하는 표준 프레임워크
- 예시: '구글로 로그인하기', '카카오 로그인'의 기반
- **핵심 철학:** 클라이언트가 사용자의 비밀번호를 직접 몰라도, 신뢰할 수 있는 대기업 서비스(구글, 네이버 등)의 인증을 거쳐 액세스 토큰(Access Token)을 발급받아 원하는 데이터에 접근할 수 있게 함.
- **핵심 역할자(Roles):**
    - **Resource Owner:** 사용자 (나)
    - **Client:** 애플리케이션/서버
    - **Authorization Server:** 권한을 부여하고 토큰을 발급하는 서버 (구글 인증 서버)
    - **Resource Server:** 실제 데이터가 있는 서버 (구글 캘린더, 프로필 등)

## 2. JWT (JSON Web Token - 데이터 포맷)

- 정의: 당사자 간에 정보를 JSON 객체로 안전하게 전송하기 위한 독립적인 토큰 형식
- 방식: 세션 방식처럼 서버 메모리나 DB에 로그인 상태를 저장하지 않고, **토큰 자체에 유저 정보를 담아 보관하는 stateless(무상태) 방식**
- **구조 (`.`으로 구분된 세 부분):**
    - **Header(헤더):** 토큰의 타입(JWT)과 알고리즘(예: HS256) 명시.
    - **Payload(페이로드):** 실제 담을 유저 정보(Claim)들 (유저 ID, 만료 시간 등).
    *※ 누구나 디코딩해 읽을 수 있으므로 민감정보는 금물*
    - **Signature(서명):** 헤더와 페이로드를 서버만 아는 '비밀키(Secret Key)'로 암호화한 값. **토큰의 위변조 여부를 검증**하는 핵심 장치.
- **특징:** 서버는 DB를 조회하지 않고도 서명(Signature)만 검증하면 "이 토큰이 내가 발급한 진짜 토큰이구나"를 바로 알 수 있어 매우 빠름.

## 3. Bearer Token (전송 방식 / 인증 타입)

- 정의: ‘이 토큰을 소지한(Bearer) 사람에게 권한을 부여한다’ 의미를 가진 HTTP 인증 타입
- 토큰을 클라이언트가 서버로 어떻게 '전송'하고 '제시'할 것인가에 대한 규약
- **작동 방식:** HTTP 요청 헤더(`Authorization`)에 아래와 같은 형식으로 담아 보냄
    
    ```
    Authorization: Bearer <토큰_문자열>
    ```
    
- **주의점:** Bearer 토큰이 중간에 탈취당하면 누구나 회원인 척 권한을 행사할 수 있으므로, 반드시 **HTTPS(SSL/TLS) 암호화 통신이 강제**되어야 함.
