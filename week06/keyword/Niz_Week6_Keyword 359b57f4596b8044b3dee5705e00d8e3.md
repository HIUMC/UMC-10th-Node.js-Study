# Niz_Week6_Keyword

## 1. ORM (Object-Relational Mapping)

- **정의:** 데이터베이스의 데이터를 자바스크립트나 타입스크립트의 객체처럼 다룰 수 있게 해주는 기술
- **장점:**
    - **생산성 향상:** SQL 쿼리를 직접 작성하는 대신 메서드 호출로 데이터를 조작할 수 있음.
    - **유지보수성:** 코드의 가독성이 좋아지고, DB 엔진이 바뀌어도 코드 수정이 적음.
- **단점:**
    - **성능 이슈:** 복잡한 쿼리의 경우 직접 작성한 SQL보다 느릴 수 있음.
    - **추상화 비용:** 내부 동작 원리를 모르면 예상치 못한 쿼리(N+1 문제 등)가 실행될 수 있음.

## 2. Prisma 문서 및 핵심 메커니즘

### 💡 Prisma의 Connection Pool 관리

→ 데이터베이스 연결을 효율적으로 관리하기 위해 Prisma는 내부적으로 엔진(Query Engine)을 사용함.

- **동작 방식:** `PrismaClient`가 인스턴스화될 때 데이터베이스와의 연결을 맺으며,
여러 쿼리가 들어올 경우 미리 만들어둔 연결(Pool)을 재사용함.
- **설정:** URL 파라미터(`?connection_limit=10`)를 통해 최대 연결 수를 조절할 수 있음.
이는 서버리스 환경에서 DB 연결 고갈을 방지하는 데 핵심적인 역할을 함.

### 💡 Prisma의 Migration 관리

→ Prisma는 `prisma migrate` 명령어를 통해 선언적으로 스키마를 관리함.

- **workflow:** `schema.prisma` 파일에 데이터 모델을 정의 → `migrate dev` 실행
                    → 자동으로 SQL 마이그레이션 파일 생성 및 DB 반영.
- **장점:** 데이터베이스의 상태를 코드(Git)로 관리할 수 있어 협업 시 스키마 동기화가 매우 간편함.

## 3. ORM(Prisma)의 장단점 요약

| **구분** | **내용** |
| --- | --- |
| **Good (장점)** | 강력한 **타입 추론**으로 런타임 에러 방지, 자동 완성 기능을 통한 개발 속도 혁신, 가독성 높은 스키마 정의. |
| **Bad (단점)** | `Node.js` 외의 언어 지원 부족, 바이너리 파일 기반의 엔진으로 인한 초기 구동 속도 및 번들 크기 증가. |

## 4. 다양한 ORM 라이브러리 비교

- **TypeORM:** 데코레이터(`@Entity`) 기반으로 Java의 Hibernate와 유사한 스타일.
- **Sequelize:** 가장 오래된 Node.js ORM 중 하나로,
                    방대한 커뮤니티와 Promise 기반의 안정적인 인터페이스를 제공.
- **Drizzle ORM:** 최근 급부상 중인 라이브러리로,
                         "SQL과 거의 유사한" 가벼운 추상화를 지향하며 성능이 매우 빠름.

## 5. 페이지네이션(Pagination) 사례 조사

### 1) GitHub REST API (Offset & Cursor)

- **방식:** 주로 `per_page`와 `page` 파라미터를 사용함.
- **특징:** `Link` 헤더를 통해 `next`, `last`, `prev` 링크를 제공하여
          클라이언트가 다음 페이지를 쉽게 요청할 수 있게 도움.

### 2) Notion API (Cursor-based)

- **방식:** `start_cursor`와 `page_size`를 사용합니다.
- **특징:** Notion은 데이터 변경이 잦은 환경이므로, 전통적인 `page` 번호 대신
         특정 데이터 이후를 지칭하는 **Cursor(커서)** 방식을 채택하여 데이터 중복 노출 문제를 방지함.
